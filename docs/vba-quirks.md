# VBA quirks

Where Excel's VBA and MS-VBAL disagree, or where MS-VBAL is silent and Excel's behavior had to be
observed. Each entry says what VBA does, what vba-ng does, and how the behavior was verified: a
golden area under tests/VbaNg.Golden, a VBE or hidden-Excel probe, source the corpus forced, or
nothing yet — which the entry says plainly.

| Area | Behavior | Implementation | Verified in Excel |
|------|----------|----------------|-------------------|
| Lexer, strings | A string literal left open at the end of a line is closed by the line terminator; the VBE accepts `s = "open` and `Len(s)` is 4. MS-VBAL 3.3.4 requires the closing quote. | Closes the literal at end of line, no diagnostic. | Yes (VBE probe, Lexer golden) |
| Lexer, comments | A line continuation inside a comment continues the comment onto the next physical line (MS-VBAL 3.3.1 comment-body allows line-continuation): after `' this comment continues _` the next line `n = 2` does not run, and the VBE colors it as comment. | The next line is part of the comment trivia. | Yes (Lexer golden) |
| Lexer, type suffixes | A type-suffix character right after a name or a number is the suffix, whatever follows: the VBE rejects `a&b`, `a&"x"`, `a^b`, `x^2`, `2^3`, and `2^b` alike (it reads `a&` or `2^` and then a stray operand), while `a & b` runs, and `x&(5)` and `x!` before a separator are typed names. The one exception is `!` before a name, `rs!Field`, which is dictionary access. MS-VBAL 3.3.5.3 only requires the suffix to follow the identifier immediately. | The same (`Lexer.IsTypeSuffixHere`). | Yes (Lexer golden bisect, VBE probes) |
| Lexer, `&` with a Byte array | The VBE rejects `"[" & b & "]"` where `b` is a `Byte()` at compile time, as it rejects `&` with any array; the golden recorder hung on the dialog until `--bisect` named the case. A Byte array still reaches a String through `CStr`, an assignment, or a parameter. | vbang compiles it and gives the array's bytes as text, accepting a program the VBE refuses: vba-ng may accept more than VBA but never less, and every program VBA accepts means the same. | The VBE rejection, yes (golden bisect) |
| Lexer, octal | `&17` is the octal literal 15 wherever it appears: `x &17` is rejected by the VBE (two operands side by side), so a bare `&` followed by an octal digit never concatenates. `&H` and `&O` followed by a digit always start a literal too (`Err.Raise &H80040201, "src"`, seen throughout the corpus). MS-VBAL 3.3.2 octal-literal allows omitting the `O`. | A bare `&` followed by an octal digit is always a literal; `&` followed by whitespace is the operator. | Yes (Lexer golden bisect) |
| Lexer, continuation | MS-VBAL 3.2.2 requires whitespace before `_` and none after it. The VBE requires the whitespace before (a line that starts with `_` is rejected, as is `2_`) and tolerates whitespace after it. | The same. | Yes (VBE probes) |
| Lexer, operators | `=<`, `=>`, and `><` are accepted as `<=`, `>=`, and `<>` (`1 =< 2` and `1 >< 2` are True); the VBE rewrites them when the line is typed. | Lexed as the equivalent token with the original text kept. | Yes (VBE probe, Lexer golden) |
| Lexer, labels | A non-reserved name or a line number first on a line and followed by `:` is a label (MS-VBAL 5.4.1.1), so `Beep: x = 1` defines a label `Beep` rather than calling `Beep`; the statement after the colon runs, and `10: x = 4` is a numbered line. | Label. | Yes (Lexer golden: the lines are accepted and the statements after the colon run) |
| Lexer, reserved words | `Local` is reserved in the VBE although MS-VBAL 3.3.5.2 does not list it: `Dim Local As Long` is rejected, and a module with `Private Function Local()` passes the line parser (AddFromString accepts it) but the project no longer compiles, so `Application.Run` reports "Cannot run the macro" with no dialog. | `Local` is a keyword (`SyntaxKind.LocalKeyword`); a declaration named `Local` is a syntax error. | Yes (VBE probes; found when a Scope golden helper was named `Local`) |
| Strings, byte strings | A String may hold an odd number of bytes (`ChrB`, `LeftB`, `MidB`, `RightB`, `StrConv(..., vbFromUnicode)`, a Byte array assigned to a String): `LenB` counts every byte, `Len` the whole code units, `AscW` reads the first two bytes as one unit, `&` joins bytes (`ChrB(65) & ChrB(66)` is one code unit, 16961), a binary comparison ranks the string with the extra byte greater (`StrComp(LeftB("hello", 3), "h")` is 1, `LeftB("hello", 3) = "h"` is False), `UCase` drops the odd byte, and `ChrB(256)` overflows (error 6, a Byte argument). MS-VBAL 2.1 describes String as a sequence of code units. | The same: a BSTR of any byte count, spans over its bytes or its whole code units per function. | Yes (Strings golden) |
| Parser, procedure ends | VBA does not check which `End` keyword closes a procedure: `End Sub`, `End Function`, and `End Property` are interchangeable, and all six pairings compile and run in the VBE. MS-VBAL 5.3.1 gives each procedure its own end-statement. stdVBA's `stdPerformance` and `stdProcess` rely on it. | Whichever of the three closes the procedure is accepted and kept as written, so printing gives the file back byte for byte. | Yes (VBE probes) |
| Parser, Exit | Which `Exit` leaves a procedure is not checked either: `Exit Sub`, `Exit Function`, and `Exit Property` are interchangeable inside any procedure and each leaves the procedure it stands in. MS-VBAL 5.4.2.10 pairs each with its own procedure kind. stdVBA's `stdEnumerator` relies on it. | Any of the three leaves the procedure; VBA0016 does not report the pairing, and still reports `Exit For` and `Exit Do` outside their blocks. | Yes (VBE probes) |
| Parser, ReDim | MS-VBAL 5.4.3.3 allows only a plain name as the ReDim target, but Excel accepts any l-expression: `ReDim Preserve This.Items(n)` and `ReDim List(i).Elements(n)` are common in the corpus (stdVBA). | Any member, dictionary, or index chain; the last parenthesized group is the bounds. | No (corpus evidence only) |
| Parser, Type members | Reserved words are valid user-defined-type member names (MS-VBAL 5.2.3.3 reserved-member-name); the Windows `PICTDESC` struct declares `Type As Long`. Enum members must be plain names (5.2.3.4). | Any keyword except the reserved type identifiers is accepted as a Type member name. | No (spec only) |
| Runtime, `Mod` | MS-VBAL 5.6.9.3.5 defines the result as the absolute value of the difference; Excel keeps the dividend's sign: `-7 Mod 2` is -1. | Dividend's sign. | Yes (Operators golden) |
| Runtime, Date arithmetic | MS-VBAL 5.6.9.3 makes every arithmetic result with a Date operand a Date; Excel gives a Double for `Date - Date` and `Date * n`, a Date only for `+` and `Date - n`. | As Excel. | Yes (Operators golden) |
| Runtime, Currency times floating point | The 5.6.9.3 table says Currency; Excel gives a Double for `Currency * Double`, while `Currency + Double` stays Currency. | As Excel. | Yes (Operators and Information goldens) |
| Runtime, `0 ^ -1` | Excel raises error 5, not 11. | Error 5. | Yes (Operators golden) |
| Runtime, typed overflow | `Byte + Byte` on declared Bytes overflows (error 6) rather than widening to Integer; widening happens only with a Variant operand (5.6.9.3). | `DeclaredTypes` flag on operators. | Yes (Operators golden) |
| Runtime, two-digit years | Date strings, date literals, and `DateSerial` all use the Windows regional two-digit-year window (1950 to 2049 here), not a fixed 1930 to 2029 rule. | Regional calendar. | Yes (Conversion, DateLiterals, DateTime goldens) |
| Runtime, `DateDiff` | The result is a Variant: Long normally, Double once the count exceeds Long. | As Excel. | Yes (DateTime golden) |
| Runtime, `IsDate` | A string that is only a number is not a date to `IsDate`, although `CDate` accepts it as a serial. | As Excel. | Yes (Information golden) |
| Runtime, `Error(n)` | A negative number gives "Application-defined or object-defined error" and a number above 65535 raises 6, where the documentation says 5. | As Excel. | Yes (Information golden) |
| Runtime, `CDec` | A string with trailing zeros parses to the smallest scale (`CDec("1.500")` is 1.5, scale 1), while a Currency converts with scale 4. | As Excel. | Yes (Conversion golden) |
| Runtime, `Hex`/`Oct` of floating point | Single, Double, Currency, and Decimal values print with 64 bits: `Hex(-1#)` is sixteen Fs. | As Excel. | Yes (Conversion golden) |
| Runtime, `String(n, code)` | The character code is taken as an Integer and its low byte goes through the system code page: `String(2, 8364)` is "¬¬", `String(2, -1)` is "ÿÿ". | As Excel. | Yes (Strings golden) |
| Runtime, `InStr` | `InStr("", "")` is 0; an empty search string is found at Start even past the end; an invalid compare argument is treated as binary rather than raising 5; `Split` with limit 0 gives an empty array. | As Excel. | Yes (Strings golden) |
| Runtime, floating point | A Double operation that divides by zero or overflows stores its IEEE result before the error is raised: under `On Error Resume Next`, `x = 1 / 0` leaves `x` at infinity (error 11), `d = d * 10` from 1E308 leaves infinity (error 6), and a function assigning `a / b` to its result returns infinity to a caller that then sees `Err.Number` 11. A Variant target keeps its old value, and `\` and `Mod` by zero leave a Long untouched. MS-VBAL 5.6.9.3 describes the error, not the stored result. | As Excel: when a Double or Single variable, field, or element is assigned a floating-point operation the compiler stores the result first and the runtime raises afterwards (`Operators.CheckFloating`); any other target raises before storing. Ten Errors cases. | Yes (Errors golden) |
| Runtime, `Erl` | `Erl` comes from a per-procedure table of the numbered lines and the code offset each one labels — a numbered declaration taking the offset of the code after it — not from the numbered lines that ran: `10 Dim z` / `20 Dim x` / `30 x = 1 / z` / `40 Exit Sub` gives 10, the same code without line 40 gives 30, a numbered line only in the handler still gives 10, and an unnumbered statement reached again by a jump after a numbered line ran gives 0. MS-VBAL 5.4.4 describes the failing line only. | As Excel: the compiler builds the table per dispatch procedure (`CSharpEmitter.ErlLines`, a switch over the statement index) and `ProcedureFrame.TryHandle` reports it. Forty Errors cases. | Yes (Errors golden) |
| Compiler, named arguments | `InStr` and `StrComp` reject every named argument (`InStr(Start:=2, ...)`, `StrComp("a", "A", Compare:=vbTextCompare)`: the VBE stops with a compile error), although the Object Browser shows their parameter names; `Replace`, `Split`, `InStrRev`, `Filter`, `Join`, `UCase`, `Mid`, `Left`, `Right`, `Format`, `IIf`, `Round`, and `DateAdd` take them. | The binder knows no parameter names for the two, so a named argument to them is VBA0013. | Yes (Strings golden probes; `Bind_NamedArgumentToInStrOrStrComp_IsReported`) |
| Compiler, COM members | A member the type library does not list compiles and is looked up at run time (438 when absent) on `Range`, `Application`, `Workbook`, `MSForms.Control`, and `MSForms.CommandButton`, but is a compile error on `Worksheet`. MS-VBAL 5.6.12 says nothing about which library types bind late; the type library does: `_Worksheet`, `_Chart`, and `Sheets` carry `TYPEFLAG_FNONEXTENSIBLE`, the others do not. | An interface without `TYPEFLAG_FNONEXTENSIBLE`, on it or inherited, takes unknown members late; one with it reports them (VBA0005). | Yes (probes in a hidden Excel on the six types above; `ExtensibleInterfaceTests`) |
| Runtime, `Err` after `Resume Next` | An error skipped by `On Error Resume Next` leaves `Err` set when the procedure returns, so a caller sees it; leaving from inside a handler clears it. | As Excel. | Yes (Errors golden) |
| Runtime, `Err` help properties | Runtime errors carry `HelpFile` = VBA's VbLR6.chm path and `HelpContext` = 1000000 + number. | As Excel. | Yes (Errors golden) |
| Runtime, `Format` | A bracketed code such as `[h]` produces nothing; `%` alone does not make a pattern numeric (`"d%"` is a date pattern); numbers round half away from zero on their decimal text. | As Excel. | Yes (Format golden) |
| Runtime, text collation | `Option Compare Text` ignores a hyphen when ordering ("co-op" is not less than "coop") and `UCase`/`LCase` leave the dotless i and dotted I alone, which is Windows NLS behavior. | NLS through the `System.Globalization.UseNls` runtime switch and `LCMapStringEx`. | Yes (StringsText and Strings goldens) |
| Runtime, `Print #` and `Debug.Print` | Numbers print in `Str` form followed by a space, `,` moves to the next 14-column zone, and a trailing `;` keeps the line open for the next Print (MS-VBAL 5.4.5.6 output-list says nothing of the zones). | `PrintList`, shared by `Print #` and `Debug.Print`. | Yes (FileSystem golden: `Print #` writes lines the way `Debug.Print` shows them) |
| Compiler, `Foo(a)` | A call statement written `Foo(a)` without `Call` passes its single argument ByVal, because the parentheses make it an expression (MS-VBAL 5.6.13.1). | The binder marks the argument parenthesized. | Yes (Procedures golden) |
| Compiler, `Resume Next` in a block | After an error in the condition of an `If`, `Resume Next` continues with the statement that follows in flattened order, the first statement of the Then block. | Dispatch loop, next statement index. | Yes for `If` (Procedures golden); `Do` and the `For` header not recorded |
| Compiler, `Resume Next` in a `Select Case` | After an error in the `Select Case` expression, `Resume Next` continues after `End Select`, unlike the `If` condition above. | The selector statement resumes at the end of the block; every other statement resumes at the next one. | Yes (Procedures golden) |
| Runtime, `Err.Raise` with omitted arguments | While `Err` already holds an error, `Err.Raise n` without a Description keeps the current Description, Source, HelpFile, and HelpContext instead of taking the message of `n`: raising 7 inside a handler for error 5 reports "Invalid procedure call or argument". | As Excel: omitted arguments keep the current values when `Err.Number` is not 0. | Yes (Procedures golden) |
| Runtime, `FreeFile` | The documentation allows only range 0 or 1; Excel treats any other range like 1: `FreeFile(2)` is 256. | Any non-zero range selects 256 to 511. | Yes (FileSystem golden) |
| Runtime, Random `Put` | A record shorter than the record length is written without padding: after `Put #f, 2, CLng(9)` with the default length of 128, `LOF` is 132, not 256. The next record still starts at 256. | Writes the bytes and steps to the next record. | Yes (FileSystem golden) |
| Runtime, `Open For Binary Access Read` | A missing file is created empty, as in the other Binary and Random opens, rather than raising 53. | Opens with create. | Yes (FileSystem golden) |
| Runtime, `Dir` of a folder | `Dir(path)` naming an existing folder without `vbDirectory` returns an empty string rather than the folder's files; `Dir(path & "\")` lists them. With `vbDirectory` it returns `.` and `..` before the entries; a hidden file is listed only with `vbHidden` and a system file only with `vbSystem`. | A folder entry is filtered like any other. | Yes (FileSystem golden) |
| Runtime, `Write #` | Numbers take the form of `Str` without its leading blank (`0.1` writes `.1`); a Date with a time of day always writes both parts, so `TimeSerial(6, 7, 8)` writes `#1899-12-30 06:07:08#`. | As Excel. | Yes (FileSystem golden) |
| Runtime, `Input #` into a Variant | Each item takes the narrowest fitting subtype: `12` is Integer, `-7` Integer, `100000` Long, a bare decimal such as `12.5` Currency rather than Double, `1.5E+20` Double, `#TRUE#` Boolean, `#NULL#` Null, `#2020-01-02 15:04:05#` Date, and an empty item Empty. | The same: Currency for a decimal without an exponent. | Yes (FileSystem golden) |
| Runtime, `Width #` | The width wraps between the items of a `Print #` list: an item that would pass the width starts a new line, while a single item longer than the width is written whole. | As Excel. | Yes (FileSystem golden) |
| Runtime, `Loc` on a sequential file | `Loc` is the 128-byte block the next byte falls in, not the bytes read divided by 128: 1 right after `Open For Input`, still 1 after nineteen bytes, and 2 once the next byte is the 129th. MS-VBAL 6.1.2.8 says the current position divided by 128. | `position / 128 + 1` (`FileChannel.Loc`). | Yes (FileSystem golden) |
| Runtime, `Put` and `Get` of an array | `Put` of a dynamic array writes a descriptor that `Get` into a dynamic array reads back, bounds included, and that `Get` into a fixed array skips. | As Excel. | Yes (FileSystem golden) |
| Runtime, `Len` and `LenB` of a type | `Len` of a user-defined type is an Integer (`Len` is otherwise a Long) equal to the bytes `Put` writes: the members' sizes with no padding, a fixed-length string one byte a character, and a variable-length string its eight-byte pointer whatever it holds (`Len` is 35 for Byte, Integer, Long, Double, Currency, String, String * 4, empty or not). `LenB` is the memory size, members at their natural alignment and fixed-length strings two bytes a character (40 for that type, 17 and 24 for `Long` + `String * 5` + `Currency`, 12 for three Longs). MS-VBAL 6.1.2.9 describes `Len` of a type as the size written to a file. | As Excel, from the record's file and memory layouts. | Yes (Types and FileSystem goldens) |
| Runtime, `LenB` and `VarPtr` of a fixed-length string | `LenB` of a `String * n` variable or array element is an Integer, 2n, while `Len` of it is a Long, n. `VarPtr` of a fixed-length string, variable or member, is the address of a temporary copy: the pointer stored there is not `StrPtr`'s, and a member's is not the address of its type. MS-VBAL 6.1.2.9 gives `LenB` a Long. | As Excel: `LenB` of the variable is a constant Integer, and `VarPtr` points at a temporary BSTR that dies with its statement. | Yes (Memory and Strings goldens) |
| Runtime, `LSet` between types | `LSet` copies the memory image: members at their natural alignment, fixed-length strings two bytes a character (eight bytes copied into a `String * 8` fill its first four characters with pairs of bytes), the source's bytes over the start of the destination and the destination's remaining bytes left alone. On strings, `LSet` and `RSet` justify the value in the target's current length, pad with spaces, cut on the right, and leave an empty variable-length target empty. MS-VBAL 5.4.3.6 says only that the bytes are copied. | As Excel: `RecordImage` spells the layout out byte by byte. | Yes (Types golden) |
| Runtime, `VarType` of an object | An object reports the type of its default member's value, not `vbObject`: `VarType(counter)` is 3 when the default member is a `Long` property. `vbObject` comes back for `Nothing`, for an object without a default member, and for one whose default member needs arguments (a `Dictionary`). | As Excel. | Yes (Classes and Objects goldens) |
| Compiler, class modules | A `.cls` with `VB_PredeclaredId = True` and `VB_Exposed = True` is what Excel writes for a sheet or workbook module, and also what a PublicNotCreatable class with a predeclared instance exports (stdVBA), so the attributes alone cannot tell them apart; MS-OVBA describes the attributes, not the ambiguity. | The workbook beside the project folder decides by its CodeNames, the manifest's `documents` map overrides, and the attribute pairing is the last resort when neither speaks (VBA0024 when it is all there is). | Yes (stdVBA compiles; the Sheets sample binds) |
| Compiler, class names | The VBE rejects a class module named after a VB6 special form (`Circle`, `Line`, `PSet`, `Scale`): the whole project stops compiling. MS-VBAL 3.3.5.2 reserves them as statements, not as type names. | Accepted; vba-ng has no VB6 graphics statements. | Yes (observed while recording the Classes golden) |
| Runtime, error in `Class_Terminate` | An error raised in `Class_Terminate` cannot be handled: Excel shows a modal dialog even under `On Error Resume Next`, which stops the golden recorder. | The error is raised into the statement that released the object, where a handler can see it. | Observed in Excel, no golden (a modal dialog cannot be recorded) |
| Compiler, enum members | Two enums of one module may declare a member of the same name (stdVBA's `EIUnknown` and `EIDispatch` both declare `QueryInterface`); MS-VBAL 5.2.3.4 puts every member in the module's scope without saying what happens when two collide. A qualified use reaches either; the VBE reports an unqualified use of a shared name as ambiguous. | The first enum keeps the bare name and a qualified use reaches either; an unqualified use of a shared name goes to the first enum instead of being reported, which is lenient toward code the VBE rejects, never a change of meaning for code it accepts. | Yes (Procedures golden) |
| Runtime, `Tan` | `Tan(1)` is `1.5574077246549` with bits `3FF8EB245CBEE3A7`, one ulp above the correctly rounded tangent and equal to `Sin(1) / Cos(1)`; `Tan(2 * Atn(1))` agrees with the quotient too. MS-VBAL only names the function. | `Tan` is the quotient of `Math.Sin` and `Math.Cos`. | Yes (Math golden) |
| Runtime, Financial evaluation | VBA evaluates the Financial functions in the x87 extended format (a 64-bit significand, every operation rounded to nearest even) and rounds to Double only where a value leaves the formula: the result, the operands and result of `pow` (so `1 + Rate` is a Double before the power), the due factor `1 + Rate`, the objective `Rate` and `IRR` iterate on, and the excess over salvage in `DDB`. `NPV` multiplies the discount factor forward and divides each flow by it, coming out as the exact value rounded once, which no ordering in Double reaches. `IRR` stops when the rate moves by less than 1E-7 whatever the scale of the flows, `Rate` when its objective is within 1E-7, both taking the secant step in x87 from the stored Doubles. `NPer` at a nonzero rate computes in Double, and `IPmt` and `PPmt` combine Double results in Double. VBA's `^` equals `Math.Pow` bit for bit. | `Extended`, a software x87 format, in `Financial`. | Yes (Financial golden, 101 cases, and about eight hundred probed values) |
| Runtime, Double expressions | Within one expression VBA computes Double arithmetic in the x87 extended format and rounds only where the value is stored, passed, or printed: `x / y * z` over typed Doubles is the extended result rounded once, `1E+308 * 10 / 10` is 1E+308 rather than an overflow, and `a / b * z = r * z` compares unrounded values. A constant takes part unrounded too; a Variant operand rounds at every step. | Not emulated: typed Double arithmetic computes in Double. The difference is one ulp where it shows, at most 2.2E-16 relative, plus the rare intermediate past the Double range. Three golden cases that miss by one ulp are accepted as such (tests/VbaNg.Golden/Expected/Ulps.txt), and two Operators cases, the range and the comparison, stay named in Expected. | Yes (Operators and Financial goldens) |
| Runtime, Boolean bits | A Boolean is VARIANT_BOOL's two bytes, and VBA keeps whatever bits memory puts in them: a record member written as 1 prints True, but `CInt` of it is 1, not -1, since the conversion takes the bits as a number. | Record members are `VbaBoolean` (two bytes, the bits kept); a Variant keeps a Boolean's bits and the conversions to numbers read them. A Boolean variable outside a record is still a one-byte bool. | Yes (Memory golden) |
| Runtime, fixed-length string layout | A fixed-length string member of a user-defined type lies inline as its UTF-16 characters, but at one-byte alignment rather than a character's two: after a Byte it starts at offset 1, and a `Byte`, `String * 3`, `Byte` type is 8 bytes. An array of them lies inline the same way, six bytes an element with no padding. | A member's inline storage is 2n bytes (`__CharsN`), so it aligns as VBA's, and an array of them is those elements inline. | Yes (Memory golden) |
| Runtime, `For Each` over an array | The elements are read as the loop reaches them, not snapshotted: an element the body changes before its turn is seen changed (`a(3) = 30` inside the loop prints `1 2 30`). MS-VBAL 5.4.2.4 does not say. | As Excel: the enumerator reads each element when its turn comes. | Yes (ControlFlow golden) |
| Runtime, `For` bounds | The limit and step of a typed counter are Let-coerced to the counter's type before the loop: `For i = 1 To "3"` runs three times, `For i = 1 To Null` raises 94. Both are captured once, so changing their variables inside the loop changes nothing, while changing the counter is honoured. A Byte counter to 255 and an Integer counter to 32767 stop at the last value; an Integer counter with a Long limit beyond 32767 stops at 32767 too. MS-VBAL 5.4.2.3 describes the coercion. | As Excel. | Yes (ControlFlow golden) |
| Runtime, `Select Case` | Clauses compare by the declared types of the selector and the clause value, as the operators do: `Select Case "10"` matches `Case 10`, and a Variant holding 10 matches `Case "10"`. A clause comparison that yields Null raises 94 (`Select Case 1` with `Case Null`), but a Null selector matches no clause and falls to `Case Else` without an error. `Select Case c` on a Collection with `Case Nothing` is rejected by the VBE. MS-VBAL 5.4.2.10 says only that the clauses are compared with `=`. | As Excel. | Yes (ControlFlow golden) |
| Runtime, project reset | When a workbook closes, VBA destroys the objects its project still holds (module-level variables of every module, an object only a module-level Collection holds, a `Static` local) without running their `Class_Terminate`. `End` does the same for every object, including those held by locals of the frames it unwinds and by a ByVal parameter, resets module-level variables (`first Is Nothing` is True on the next call), and runs nothing after it. MS-VBAL 5.4.2.15 says only that `End` terminates the program. | `ProjectReset`: each module's generated `__Reset` returns its storage to its initial values while the project's instances skip `Class_Terminate`; `End` marks the project before it unwinds, the host resets it, and unloading a project resets it first. | Yes (hidden-Excel probes: `Class_Terminate` reported through the registry, a file, and a cell of another workbook, with a control object released normally) |
| Host, `Application.Run` compiles one procedure | VBA compiles the procedure `Application.Run` names, not the module around it, so a construct in a procedure nothing calls is never bound and a probe that merely puts it in the module looks accepted whatever it is. MS-VBAL does not say when a procedure is compiled. | Nothing to implement; probes and goldens must call the construct they test. | Yes (hidden-Excel probes, after two wrong conclusions drawn from probes that bound nothing) |
| Host, `Application.Run` names | `Application.Run` runs a procedure named `Proc`, `Module.Proc`, `'Book.xlsm'!Module.Proc`, `Book.xlsm!Module.Proc`, or `'Book.xlsm'!Proc`, in any case, and a Private Sub or Function of a standard module as well as a Public one; a document module's procedures, Private ones too, only named with their module (`ThisWorkbook.Proc`). A bare name two standard modules define, a document module's procedure named bare, a class module's method, a Property Get, and a name nothing defines raise 1004 "Cannot run the macro 'Name'. The macro may not be available in this workbook or all macros may be disabled." with the source "Microsoft Excel". | The calling project's own procedures resolve in-process through each module's Run table, and a bare name two modules define raises the same 1004; any other name goes to Excel. | Yes (Excel probe; the E2E test `HostRun_ApplicationRun_MatchesVba` runs the same modules under VBA and vbang) |
| Host, `Application.Run` arguments | The arguments pass by value, so a ByRef parameter does not write back, and each keeps its subtype (an Integer arrives as Integer, a Decimal as Decimal, Nothing as Nothing, an array as `Variant()`). Missing arguments at the end are dropped before counting: `Run("Twice", 3, missing)` calls `Twice(3)`, `Run("Kind", missing)` raises 449, and `Run("Twice", missing, 3)` raises 450. Too few arguments raise 449, too many 450, and one the parameter cannot take 13 (`"12"` passes to a Long, 2.5 rounds to 2), each with the project's name as the source; a Sub returns Empty. | As Excel: the Run table converts the arguments as a late-bound call does, after dropping the trailing Missing ones. | Yes (Excel probe; the same E2E test) |
| Host, `Application.Run` errors | An error the called procedure leaves unhandled never reaches the caller: VBA shows its run-time error dialog (Continue, End, Debug) even when the caller runs under `On Error Resume Next`, and the caller does not go on while the dialog is up. | The error escapes every handler of the caller as an `UnhandledErrorException` and reaches the host as any unhandled error does; the host shows VBA's dialog text and logs the error. | The dialog, yes (Excel probe); what its End button does after that, no |

## Where vba-ng differs from VBA

The rows above are VBA against MS-VBAL. These are vba-ng against VBA: where the compiler or the
compiled code does not match Excel, and whether that is deliberate or simply not done.

| Area | Gap | Status |
|------|-----|--------|
| Compiler, `Command` and `IMEStatus` | Both report VBA0002 wherever they are called: Excel has no command line, and no input method editor to report. | Deliberate |
| Compiler, a field of an interface class | A public field of a class another class implements is left out of the generated interface, so the `IFoo_Field` property implementing it reports VBA0002; an interface class must declare a property where VBA takes a field. | Not done |
| Compiler, an array of `String * n` in a Variant | `v = a` compiles, where the VBE stops the module; as with `&` on a Byte array, vba-ng may accept more than VBA, never less. | Deliberate |
| Runtime, remote COM | `CreateObject(class, servername)` raises 429 rather than activating the class on that machine, and `GetObject(path, class)` ignores the class, binding the file through its own moniker. | Not done |
| Runtime, `x!Name` | The default member is reached by name at run time even when the class is known: the value is VBA's, the cost is a dispatch. | Deliberate |
| Runtime, a class module's `Static` local | It lives in the instance, as MS-VBAL 5.2.3.1 has it, but no golden records it: the Static cases of the Classes golden are all in standard modules. | No golden |
| Host, registered names | The names a project registers with Excel are never unregistered, since Excel-DNA offers no way: they outlive their workbook's close and are registered again after a rebuild. | Not done |
| Host, UDF threads | `'@ThreadSafe` is not implemented and not reported either, the comment being trivia like any annotation vba-ng does not know, so every UDF runs on Excel's main thread, as VBA's do. | Not done |
| Host, UDF registration | Every UDF registers as a macro-type function, so any of them may call `Application.Volatile`, `Caller`, and `ThisCell` as any VBA Function may; Excel keeps macro-type functions out of conditional formatting and data validation formulas. | Deliberate, not probed |
